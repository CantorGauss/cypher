# Cypher

File encryption that runs entirely in the browser, in the spirit of [hat.sh](https://hat.sh).
No application server and no build step: seven static files, about 1.3 MB. The interface is in French.

```
public/
├── index.html
├── style.css
├── app.js                       user interface
├── worker.js                    encryption, in a Web Worker
└── vendor/
    ├── libsodium-sumo.js        libsodium 0.8.4 (embedded WebAssembly)
    ├── libsodium-wrappers.js
    └── LICENSE
```

## Deploying

Copy the contents of `public/` to any static host: Nginx, GitHub Pages, Cloudflare Pages, Netlify, S3…
There is nothing to compile or configure.

The page must be served over **HTTPS** (or from `localhost`). The browser APIs it relies on are restricted
to secure contexts, and it does not work when opened directly from `file://`.

To try it locally:

```bash
python3 -m http.server --directory public 8000
```

then open <http://localhost:8000>.

If your host lets you set response headers, add this one (optional but recommended). It covers the Worker,
which the page's `<meta>` tag does not, and prevents the page from being embedded in an iframe:

```
Content-Security-Policy: default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src data:; worker-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
```

## Cryptography

| Purpose | Choice |
| --- | --- |
| Authenticated encryption | Streaming XChaCha20-Poly1305 (`crypto_secretstream`), 256-bit key, 192-bit nonce |
| Password to key | Argon2id, 256 MiB, 3 passes, random 128-bit salt |
| Key mode | Random 256-bit key generated by libsodium, encoded as base64url (43 characters) |
| Randomness | The browser's `crypto.getRandomValues`, through libsodium |

Useful properties:

- **Nothing leaves the browser.** The file is read and processed locally, and the code opens no connection.
  The page's CSP also forbids all network connections, and the header above extends that restriction to the
  Worker.
- **No plaintext before verification.** A decryption result is only offered once the final block has been
  authenticated. A file that was altered, truncated, reordered or extended produces nothing.
- **Large files.** Data is processed in 1 MiB blocks and the output goes through the browser's private storage
  (OPFS), so file size is not limited by RAM, but you need about twice the file's size in free disk space during
  the operation. If OPFS is unavailable (in some private browsing modes), the result stays in memory and the limit
  is 2 GiB.
- **Memory.** Each operation gets its own Worker, which is destroyed when it finishes.

## What this tool does not guarantee

- **It has not been audited.** libsodium is a well-proven reference, but the code in this repository and its file
  format have had no independent audit. Do not delete an original before checking that you can decrypt it.
- **A password is not worth a 256-bit key.** The derived key is 256 bits long, but its real strength is limited
  to that of the password. Argon2id slows attacks down but cannot make up for a weak password. For an effective
  256 bits of security, use key mode.
- **You trust the host on every visit.** As with any web tool, the server can deliver different code. Host it
  yourself, or run it locally, if that risk matters to you.
- **The browser and machine are assumed to be clean.** An extension or malware can read the password or the file.
- **Memory wiping is not guaranteed.** Keys are zeroed in WebAssembly, but JavaScript strings (the password, a
  pasted key) cannot be.
- **"Effacer" (Clear) is not secure deletion.** The temporary OPFS file is removed, without physically overwriting
  the disk. If the tab is closed first, the file is removed on the next visit.
- **Name and size are not hidden.** The original name stays visible in `name.ext.cypher`, and the size of the
  encrypted file reveals the size of the plaintext.
- **No asymmetric sharing.** There are no public keys: the secret must be shared over a safe channel.

## File format (v1)

Integers are little-endian. The header is 56 bytes:

| Offset | Size | Content |
| --- | --- | --- |
| 0 | 4 | `CYPH` |
| 4 | 1 | Version, `1` |
| 5 | 1 | Mode: `1` password, `2` key |
| 6 | 2 | Reserved, `0` |
| 8 | 4 | Argon2id passes (`0` in key mode) |
| 12 | 4 | Argon2id memory in KiB (`0` in key mode) |
| 16 | 16 | Argon2id salt (zeros in key mode) |
| 32 | 24 | `crypto_secretstream_xchacha20poly1305` header |

The `crypto_secretstream` blocks follow: 1 MiB of plaintext each, except the last one, plus 17 bytes once
encrypted. The last block carries `TAG_FINAL` and all the others `TAG_MESSAGE`. An empty file produces a single
empty final block. The 56 header bytes are used as additional authenticated data for every block.

In password mode, the key is
`crypto_pwhash(32, NFC(password) as UTF-8, salt, passes, memory × 1024, ALG_ARGON2ID13)`.
In key mode, the 32 bytes are used directly.

This description is enough to read a file back without the site: `tests/e2e.mjs` contains an independent Node
decoder written from this specification.

## Updating libsodium

Replace the two files in `public/vendor/` with those from the `libsodium-sumo` and `libsodium-wrappers-sumo` npm
packages (`dist/modules-sumo/`), then run the tests again.

## Tests

`package.json` is only used for testing; the site does not depend on it.

```bash
npm install
```

```bash
npm test
```

The tests drive the interface in real browsers, Chrome and WebKit by default. They cover round trips at boundary
sizes, interoperability with the independent decoder, tampering, temporary file cleanup and large files. WebKit
requires `npx playwright install webkit`, and Firefox is enabled with `BROWSERS=chrome,webkit,firefox` after
`npx playwright install firefox`. Firefox has not been tested so far.
